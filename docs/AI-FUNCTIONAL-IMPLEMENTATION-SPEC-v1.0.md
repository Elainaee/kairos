# Kairos AI 功能实现 Spec v1.0

> 状态：第一版评审稿  
> 范围：AI 面板的模型接入、会话、附件、应用内工具、权限、安全与本地数据  
> UI 依据：`AI-PANEL-SPEC-v1.0.md`  
> 本文不定义视觉细节，也不授权直接开始实现。

## 1. 目标与原则

Kairos AI 是同时承担日程协助、学习辅助与陪伴聊天的综合助手。首版采用多模型 BYOK（Bring Your Own Key）模式，由 Windows 桌面端直接请求模型提供商，不经过 Kairos 自建服务器。

实现必须遵守以下原则：

- 用户明确知道内容将发送给哪一家提供商和哪个模型。
- 不在不同提供商之间自动切换。
- 查询本地数据受分类权限约束；任何新增、修改或删除必须由用户最终确认。
- 会话与配置保存在本机，API Key 不写入普通配置文件或数据库。
- 模型能力差异通过统一适配层处理，不把厂商协议泄漏到业务层。

## 2. 首版范围

### 2.1 包含

- 豆包（火山方舟）、OpenAI、Anthropic、Google Gemini 四个预设提供商。
- 用户自行配置 API Key、模型和必要的提供商参数。
- API Key 可选择仅本次使用或安全保存。
- 多会话、本地历史记录、会话内切换提供商或模型。
- 流式回复、停止生成、重试和结构化错误提示。
- 图片、文档、课件与截图输入。
- 日程、任务、习惯打卡、笔记和学习计划的受控读写。
- 会话级与全局 Token、请求次数和预估费用统计。

### 2.2 不包含

- Kairos 公共 API Key 或服务端 AI 代理。
- 自定义 OpenAI-compatible Base URL。
- 模型不可用时自动切换提供商。
- 语音输入、语音通话或实时音视频。
- 跨设备同步、云端会话同步。
- 会话 Markdown / JSON 导出和迁移。
- AI 绕过确认直接修改应用数据。

## 3. 总体架构

AI 功能分为六层：

1. `AI Panel UI`：会话、消息、附件、确认卡片与状态展示。
2. `Conversation Service`：会话持久化、上下文构建、草稿和摘要。
3. `Provider Gateway`：统一请求接口、流式事件、错误归一化和用量采集。
4. `Attachment Pipeline`：附件保留策略、原生上传、本地提取和临时文件清理。
5. `Kairos Tool Runtime`：查询或提出应用数据变更计划。
6. `Secure Storage / Local Database`：凭据与普通本地数据分离存储。

业务层只依赖统一的 Provider Gateway，不直接调用某家 SDK。提供商适配器分别负责认证、消息格式、附件能力、工具调用格式和用量字段映射。

## 4. 多提供商与 BYOK

### 4.1 预设提供商

首版固定提供：

- 豆包：火山方舟 API。
- OpenAI：OpenAI API。
- Anthropic：Claude API。
- Google：Gemini API。

每个适配器声明能力矩阵：文本、视觉、原生文件、流式输出、工具调用、上下文上限与用量返回能力。模型列表优先通过提供商 API 获取；无法获取时使用可更新的内置候选列表，并允许用户手动填写模型标识。

### 4.2 配置项

每个提供商至少包含：

- 启用状态
- API Key 状态
- 默认模型
- 连通性测试结果与时间
- 可用模型及能力信息
- 默认生成参数（首版仅保留必要参数）

设置页支持保存、测试、替换和删除凭据。已保存的 Key 只显示掩码，不允许读取或复制明文。

### 4.3 凭据生命周期

- 仅本次使用：Key 只保存在进程内存，应用退出后清除。
- 安全保存：Key 写入 Windows Credential Manager，普通本地数据库只保存凭据引用与状态。
- 从安全保存切换到仅本次使用时，先删除 Credential Manager 中对应条目。
- 删除提供商配置时同步删除安全凭据，但不自动删除历史会话。
- 日志、错误上报和调试信息禁止记录 Key、Authorization Header 或完整请求体。

### 4.4 直连与切换规则

- 所有请求由桌面端直接发送给当前提供商。
- 每条请求记录实际提供商与模型。
- 同一会话可随时切换提供商或模型，后续请求继续携带当前有效完整上下文。
- 切换操作保存在会话元数据中，不伪装成普通聊天消息。
- 请求失败、限流或能力不足时不自动切换；保留输入和附件，提示用户重试或手动选择其他模型。

## 5. 会话与上下文

### 5.1 本地会话

会话保存在本机数据库，至少包含：

- 会话 ID、标题、创建和更新时间
- 当前提供商与模型
- 消息及其状态
- 本地工具调用与确认结果
- 附件引用和保留策略
- Token、请求次数与预估费用汇总
- 草稿、滚动位置和最后阅读消息

打开 AI 面板时恢复最近使用会话；每个会话独立保存未发送草稿。用户可新建、搜索、切换、重命名和删除会话。

首版不提供导出。删除会话需二次确认，并根据附件策略同步清理关联文件。支持在设置中清空全部会话。

### 5.2 消息状态

消息状态至少包含：`draft`、`queued`、`streaming`、`completed`、`stopped`、`failed`。

发送后先持久化用户消息，再发起网络请求。流式内容按节流策略保存，避免每个 token 写库。停止生成时保留已接收内容并标记为 `stopped`。重试产生新的 assistant 消息记录，不覆盖失败记录。

### 5.3 上下文构建

发送请求时按顺序构建：

1. Kairos 系统指令与当前权限说明
2. 当前会话摘要（若有）
3. 上下文窗口内的历史消息
4. 经用户授权取得的应用数据
5. 当前消息与附件

达到模型上下文限制前，不自动截断历史。界面提示用户选择：

- 生成摘要后继续：先生成可预览、可编辑的摘要，经用户确认后替代较早上下文。
- 新建会话：可选择携带已确认摘要或从空白开始。

原始历史仍保存在本机，只是不再发送给模型。

## 6. 附件处理

### 6.1 支持范围

- 图片与截图
- PDF
- Word 文档
- PowerPoint 课件

具体格式、大小和数量限制由适配器能力与本地解析器共同决定，并在选择文件前后保持一致提示。

### 6.2 保留策略

发送前，用户可对附件选择“保留在会话中”或“不保留”。

- 保留：复制到 Kairos 管理的会话附件目录，删除会话时询问并清理。
- 不保留：放入应用临时目录；请求或本地解析完成后清理。
- 上传、解析或请求失败时，为支持重试可暂时保留至本次会话结束，但必须显示状态并允许立即删除。

### 6.3 处理优先级

1. 当前提供商与模型支持原生文件能力时，使用原生文件接口。
2. 不支持时，在本机提取文本和必要元数据，仅发送相关内容。
3. 图片与截图优先使用视觉输入能力。
4. 无视觉能力或本地提取失败时，停止处理并说明原因，不静默切换模型或提供商。

发送前显示目标提供商、模型、附件名称及将发送的形式（原文件、图片或提取文本）。

### 6.4 本地提取

提取结果保留页码、幻灯片号或段落位置，供回答引用。超长内容按结构分块，只选择与当前问题相关的片段；若需模型先索引整份材料，必须向用户说明可能产生的额外请求与用量。

## 7. Kairos 数据权限与工具调用

### 7.1 分类授权

用户在设置中分别配置以下数据：

- 日程
- 任务
- 习惯打卡
- 笔记
- 学习计划

每类数据具有三级权限：`禁止访问`、`仅可读取`、`可读写`。默认值应在首次启用 AI 时由用户选择，不能用模糊的总开关替代。

### 7.2 读取规则

- 读取前由 Tool Runtime 校验权限，模型不能直接访问数据库。
- 查询参数需限制时间范围、字段和数量。
- 被禁止的数据不进入提示词，也不向模型暴露其是否存在。
- 读取与总结不需要逐次确认，但界面应能查看本次请求使用了哪些数据类别。

### 7.3 写入规则

新增、修改和删除均采用两阶段流程：

1. 模型提出结构化变更计划。
2. Kairos 校验 schema、权限、目标是否存在及字段合法性。
3. 对话流展示可编辑确认卡片。
4. 用户逐项或批量确认。
5. Tool Runtime 执行已确认项目并返回逐项结果。

确认卡片生成本身不得修改数据。批量操作允许逐项取消。删除操作必须明确显示对象与影响；执行结果支持可行范围内的撤销。

### 7.4 工具集合

首版按数据域提供 `query`、`propose_create`、`propose_update`、`propose_delete`。模型只能提出变更，实际 `commit` 接口不暴露给模型，由用户确认事件触发。

## 8. 流式回复与错误处理

Provider Gateway 将厂商事件归一化为：

- `response_started`
- `text_delta`
- `tool_proposal`
- `usage_update`
- `response_completed`
- `response_stopped`
- `response_failed`

界面允许停止生成。网络中断、认证失败、额度不足、限流、上下文超限、模型不存在、附件不支持和内容安全拒绝必须映射为不同错误类型。

错误状态保留用户输入、已上传附件与已生成内容，并提供适当后续操作：重试、修改配置、缩短上下文或手动选择模型。禁止后台自动改用另一提供商。

## 9. 用量与费用

对话流默认不显示 Token 或费用。会话详情显示：

- 输入与输出 Token
- 请求次数
- 使用过的提供商与模型
- 预估费用

设置页支持按提供商、模型和时间范围汇总。费用始终标注“预估”，定价数据应带版本或更新时间；缺少可靠定价时只显示 Token，不猜测费用。

## 10. 安全与隐私

- API Key 使用 Windows Credential Manager 或进程内存，禁止进入普通数据库。
- 本地数据库和附件目录限制为当前系统用户访问。
- 所有外发请求在 UI 中可追溯到提供商、模型、附件和本地数据类别。
- 敏感日志默认关闭；诊断导出需对凭据与用户内容脱敏。
- 渲染模型输出时清理危险 HTML、链接协议和可执行内容。
- 文档中的提示注入不得获得额外数据权限，也不能绕过确认流程。
- 工具参数由应用生成的 schema 验证；模型文本不得直接拼接为数据库或系统命令。

## 11. 建议数据模型

核心实体：

- `ProviderConfig`：提供商、默认模型、凭据模式、凭据引用、启用状态。
- `ModelCapability`：模型能力、上下文上限、附件限制与更新时间。
- `Conversation`：会话元数据、当前提供商/模型、摘要和统计。
- `Message`：角色、内容、状态、模型元数据、错误和用量。
- `Attachment`：文件元数据、本地路径、保留策略、处理方式与状态。
- `ToolProposal`：数据域、操作、原始参数、编辑后参数、确认和执行结果。
- `UsageRecord`：请求级 Token、预估费用、提供商与模型。
- `DataPermission`：数据域与权限等级。

数据库迁移必须可回滚或向前兼容；凭据明文不属于任何实体字段。

## 12. 验收标准

1. 四个预设提供商均通过统一接口完成文本流式对话。
2. 用户可选择仅本次使用或安全保存 Key，普通数据库与日志中不存在 Key 明文。
3. 桌面端直接请求提供商，不经过 Kairos 服务端。
4. 同一会话可手动切换模型并继续上下文，失败时绝不自动切换。
5. 会话、草稿、消息状态和用量在重启后正确恢复。
6. 达到上下文上限时由用户选择摘要或新建会话，不自动截断。
7. 附件优先走原生能力，不支持时本地提取，并正确执行用户选择的保留策略。
8. 五类 Kairos 数据分别授权；读取受限，所有写入、修改和删除都必须确认。
9. 批量确认可逐项取消，失败项目不影响已成功项目且结果清楚可查。
10. 停止生成、认证失败、限流、上下文超限和附件失败均可恢复，不丢失用户输入。
11. 会话详情与设置页提供用量统计，预估费用不会伪装成准确账单。
12. 删除会话和清空历史具备二次确认及关联附件清理逻辑。

## 13. 实施顺序建议

1. 本地数据模型、会话存储与 Secure Storage。
2. Provider Gateway 协议及四家适配器的纯文本流式能力。
3. 会话 UI 状态、停止、重试、模型切换和用量记录。
4. 分类权限与只读查询工具。
5. 变更提案、确认卡片和 commit 隔离层。
6. 附件生命周期、原生文件能力和本地解析回退。
7. 上下文摘要、费用估算、安全审计与完整异常测试。
