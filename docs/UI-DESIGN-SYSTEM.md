# Kairos UI Design System

状态：`authoritative`  
适用范围：Kairos 桌面应用全部用户界面  
设计主题：`Claude +`  
代码权威来源：`app/themes/claude-plus.css`

## 1. 目的与设计权威

本文档把 Kairos 已经形成的视觉语言整理成可执行规范。它用于延续现有产品，而不是为项目重新发明一套界面。

遇到冲突时，按以下顺序判断：

1. 当前实际运行、功能正确的 Kairos UI 与语义主题 token
2. 已有可复用组件及交互契约
3. 本文档
4. `references/README.md` 收录的喜爱素材
5. 通用设计经验

`references/` 中的素材整体都具有正向参考价值，但不同来源只负责提供布局、组件或动效灵感。它们不能绕过当前主题、应用结构和已有组件，直接决定最终界面。

## 2. 视觉主题与氛围

Kairos 是一款温暖、安静、具有个人陪伴感的桌面应用。界面以纸张和骨白色表面为底，以陶土色作为主要互动颜色，搭配低饱和中性色、柔和圆角和克制的层次。它应该像一本被认真整理的个人计划本，同时保留现代桌面工具的清晰、效率与响应感。

设计需要在“亲和”与“信息密度”之间保持平衡。Calendar、Schedule 和 Habits 可以承载较多数据，但不能退化成通用企业 SaaS 仪表盘；AI Chat、Music 和桌面宠物可以更有性格，但不能引入与主应用脱节的高饱和霓虹、重度玻璃拟态或全新字体体系。

### 设计关键词

- warm editorial
- paper-like surfaces
- calm personal productivity
- crafted desktop utility
- compact but breathable
- subtle tactile motion
- terracotta accents
- restrained elevation

### 应避免的方向

- 从零生成的通用管理后台
- 大面积蓝紫渐变和“AI 科技感”霓虹
- 过多毛玻璃、发光描边和悬浮光晕
- 为每个页面分别发明颜色与圆角
- 重阴影、浮起式按钮和 hover 背景块
- 与 Outfit 冲突的新字体
- 为模仿参考素材而替换现有导航或页面结构

## 3. 色彩系统

具体运行值以 `app/themes/claude-plus.css` 为准。下面的十六进制值用于沟通和快速识别；实现时优先使用语义 token，不要复制近似色值。

### 3.1 基础表面

| 语义角色 | Token | 识别色 | 用途 |
|---|---|---:|---|
| 暖纸背景 | `--surface`, `--background` | `#FBF9F2` | 应用底色、主画布 |
| 纯白抬升面 | `--surface-raised`, `--popover` | `#FFFFFF` | 卡片、输入、弹层内容 |
| 柔和纸卡 | `--surface-subtle`, `--card` | `#F5F4ED` | 次级卡片、分组表面 |
| 暖米次级面 | `--secondary` | `#E8E3D0` | 选中分组、轻量强调 |
| 暖灰静音面 | `--muted` | `#EBE6D6` | 非交互背景、轨道和占位层 |
| 分隔线 | `--border` | `#DED8CF` | 1 px 边框和分隔 |
| 输入描边 | `--input` | `#C3BDB3` | 输入框静止边界 |

大面积表面应保持温暖而低对比。表面层级首先依赖明度、边框和空间关系，阴影只作为必要的浮层分离手段。

### 3.2 互动与强调

| 语义角色 | Token | 识别色 | 用途 |
|---|---|---:|---|
| 深陶土主色 | `--primary` | `#9E3D19` | 主操作、当前状态、图标和描边强调 |
| 明陶土强调 | 主题派生色 | `#D1633C` | 已有 CTA 识别色、较温和的互动强调 |
| 主色前景 | `--primary-foreground` | `#FFFFFF` | 实心主按钮和强选中状态文字 |
| 深青绿辅助 | `--tertiary` / 既有图表角色 | `#00666F` | 图表、成功倾向或次级数据强调，不与主 CTA 竞争 |
| 焦点环 | `--ring` | 与 `--primary` 同源 | 键盘焦点和输入焦点 |

同一局部视图应只有一个主强调色。青绿、图表色和状态色只表达信息语义，不承担普通按钮装饰。

### 3.3 文字层级

| 语义角色 | Token | 识别色 | 用途 |
|---|---|---:|---|
| 强文字 | `--text-strong`, `--popover-foreground` | `#1B1C18` | 标题、关键数值 |
| 主文字 | `--foreground` | `#3D3B2E` | 正文、控件标签 |
| 次级文字 | `--text-muted`, `--muted-foreground` | `#676556` | 说明、时间、辅助信息 |

不要用降低整体透明度代替明确的文字 token；这会同时削弱图标、边框和可读性。

### 3.4 功能状态

| 状态 | Token | 识别色 | 使用原则 |
|---|---|---:|---|
| 成功 | `--status-success` | `#477054` | 完成、连接成功、正向结果 |
| 警告 | `--status-warning` | `#A36316` | 注意、临期、可恢复风险 |
| 危险 | `--status-danger` | `#B3261E` | 删除、错误、不可逆风险 |
| 信息 | `--status-info` | `#3F6F9E` | 中性系统信息 |

状态不能只靠颜色表达。需要同时提供文字、图标、形状或上下文标签。

## 4. 字体与图标

### 4.1 字体家族

- 默认字体：`Outfit, sans-serif`
- 等宽字体：`"Geist Mono", ui-monospace, monospace`，仅用于确有代码或机器标识需求的内容
- 图标：`Material Symbols Outlined`

Outfit 的几何感与圆润细节提供现代但友好的气质。不要在单个页面中引入另一套展示字体。

### 4.2 字体层级

| 层级 | 建议值 | 使用场景 |
|---|---|---|
| Display | 48 px / 600 / 1.1 / `-0.02em` | 极少量品牌或大型欢迎区域 |
| Page headline | 32 px / 600 / 1.2 / `-0.01em` | 宽屏页面主标题 |
| Compact headline | 24–25 px / 600–700 / 1.2 | 常规桌面页标题、紧凑视图 |
| Section title | 18–20 px / 500–650 / 1.3–1.4 | 卡片组、弹窗和面板标题 |
| Body large | 18 px / 400 / 1.6 | 引导性正文 |
| Body | 14–16 px / 400–500 / 1.5–1.6 | 正文与表单内容 |
| Label | 12–14 px / 500–650 / 1–1.35 | 控件、表头、元数据 |
| Micro | 10–11 px / 500–650 / 1.3–1.45 | 紧凑统计和补充说明，谨慎使用 |

标题使用较紧字距，正文保持自然字距和宽松行高。不要用全大写制造层级；必须使用时仅限很短的 kicker 或状态标签，并增加轻微字距。

### 4.3 图标规则

- 常规图标使用 18–24 px；主视觉或空状态可用 26–32 px。
- 同一工具栏保持一致的光学尺寸和线条粗细。
- 图标按钮必须有可访问名称。
- hover 优先改变图标笔画颜色，不在图标外生成色块或阴影。
- 不混用 emoji、Material Symbols 和第三方 SVG 表达同一类系统操作。Habits 中用户选择的 emoji 属于内容，不属于系统图标。

## 5. 间距、尺寸与形状

### 5.1 间距节奏

Kairos 使用 4 px 微调、8 px 基准节奏：

| Token/概念 | 值 | 常见用途 |
|---|---:|---|
| micro | 4 px | 图标内部、紧凑标签 |
| `stack-sm` | 8 px | 相关控件、行内间距 |
| gutter | 16 px | 卡片内部、字段间距 |
| compact section | 24 px | 小节和工具栏间距 |
| `stack-lg` / container margin | 32 px | 页面边距、主要区块 |

允许为光学对齐使用 10、12、14、18、20、28 px 等现有值，但不要随意建立另一套节奏。

### 5.2 圆角

- 小标签、复选框：4–8 px
- 紧凑按钮、菜单项：8–12 px
- 输入框和常规卡片：12–16 px
- 对话框和大型浮层：18–22 px
- 胶囊、开关、圆形按钮：`9999px`，仅在语义确实需要时
- 主题基准：`--radius: 1rem`

圆角应体现同一柔和几何语言，但不要把每个矩形都变成胶囊。

### 5.3 点击尺寸

- 紧凑桌面控件：最小 36 × 36 px
- 主要操作和跨设备触控相关控件：40–44 px 以上
- Windows 窗口控件可服从标题栏布局，但可访问区域必须完整

## 6. 阴影、边界与深度

### 6.1 基本原则

Kairos 的深度首先由表面明度、1 px 暖灰边框、遮罩和空间关系建立。阴影是浮层分离工具，不是普通 hover 反馈。

- 静态卡片：无阴影或 `--shadow-sm`
- 浮动面板、菜单：`--shadow-md`，并保持克制
- 模态对话框：可使用 `--shadow-lg` 配合遮罩
- 背景壁纸上的玻璃表面：仅在可读性需要时使用有限的 blur 和透明度
- 不叠加多层彩色光晕

### 6.2 强制按钮 hover 原则

所有按钮 hover 必须遵守：

1. 不新增背景填充、半透明色块、圆形底板、矩形底板或渐变底板。
2. 不新增 box-shadow、drop-shadow、光晕或“浮起”的阴影。
3. 通过文字、图标、线条、下划线、描边或内部图案变为 `--primary` 来反馈。
4. 已经是实心的主按钮可保留原填充，并轻微调整现有填充或前景色；不得叠加 hover 层和阴影。
5. 卡片式按钮也优先改变边框、标题或内部图案，不能因为 DOM 使用 `<button>` 就浮起整张卡片。
6. `selected`、`checked`、`pressed`、当前路由等持续状态可以使用背景；持续状态不能只在 hover 时出现。
7. `:focus-visible` 使用清晰的环或 outline，这是无障碍反馈，不属于 hover 阴影。

推荐写法：

```css
.icon-button {
  background: transparent;
  color: var(--text-muted);
  box-shadow: none;
}

.icon-button:hover {
  background: transparent;
  color: var(--primary);
  box-shadow: none;
}

.icon-button:focus-visible {
  outline: 2px solid var(--ring);
  outline-offset: 2px;
}
```

不推荐写法：

```css
.icon-button:hover {
  background: var(--accent);
  box-shadow: 0 8px 20px rgb(0 0 0 / 15%);
  transform: translateY(-2px);
}
```

## 7. 核心组件规范

### 7.1 按钮

**Primary**

- 实心 `--primary`，前景使用 `--primary-foreground`。
- 用于一个局部区域中最重要的确认或创建操作。
- 静止状态也不应依赖重阴影。
- hover 保持同一形态，只轻微调整已有颜色或图标/文字，不浮起、不新增阴影。

**Secondary / Outline**

- 透明或现有表面，使用 1 px `--border`。
- hover 改为主色文字、图标或描边，背景保持不变。

**Ghost / Icon**

- 默认透明背景、无阴影。
- hover 只让图标或文字变色。
- 按下时可使用轻微缩放，但不能以背景色块代替反馈。

**Destructive**

- 静止状态明确标示危险语义，或在确认对话框中使用实心危险操作。
- hover 只改变文字、图标、线条或现有填充，不突然出现红色背景块。

### 7.2 导航与应用顶栏

- 顶栏高度以当前 64 px 为基准。
- 顶部导航保持紧凑、水平和拖拽区域兼容。
- 当前路由可通过 GooeyNav 持续状态或稳定的主色指示器表达。
- 普通 hover 不生成新的按钮底板；改变标签、图标或指示线颜色。
- Windows 最小化、最大化和关闭控件也遵循前景变色原则。系统危险语义通过关闭图案变为危险色表达，不依赖 hover 背景块。

### 7.3 卡片与容器

- 主要使用 `--surface-raised` 或 `--surface-subtle`。
- 使用 1 px `--border`，圆角通常 12–16 px。
- 内边距多为 14–20 px；高层级卡片可到 24 px。
- 默认阴影应很轻或没有阴影。
- 普通卡片 hover 可改变边框、局部图案或轻微位移；不要突然添加大面积深阴影。
- 可点击卡片应保持与普通卡片相同的视觉语言，并提供清晰 focus-visible。

### 7.4 输入与表单

- 使用 `--surface-raised`、`--input` 和 `--text-strong`。
- 输入高度通常 44–50 px；紧凑工具栏搜索可低至 34–36 px。
- focus 使用主色边框和清晰 ring。
- 标签不能只依赖 placeholder。
- 禁用状态降低对比但保持文字可读，且无 hover 响应。
- 下拉列表和日期选择器复用既有 combobox、popover 和 schedule patterns。

### 7.5 对话框、菜单与 Popover

- 对话框使用 18–22 px 圆角、清晰标题、简洁描述和靠右操作区。
- 模态遮罩允许轻度 blur；弹层自身保持暖白或纸张表面。
- 浮层可以使用阴影与背景分离，但浮层内按钮 hover 仍不能生成新阴影或背景块。
- Esc、遮罩关闭和焦点恢复服从现有组件行为，不因视觉重写而丢失。

### 7.6 Toast 与 Reminder

- Toast 是短暂反馈，不替代持久状态。
- 状态由图标、文字和语义色共同表达。
- Toast 操作按钮复用按钮 hover 原则。
- Reminder panel 保持信息分组与动作层级，不创建第二套通知系统。

### 7.7 数据表格与日程

- 表头使用柔和表面和较小标签文字。
- 行 hover 可使用极轻的表面变化，因为整行不是按钮；行内按钮仍按无背景 hover 处理。
- 状态 pill 必须有文字。
- 分页、筛选和更多操作复用当前紧凑工具栏尺寸。

### 7.8 Habits

- Habits 允许比其他页面更具触感的动效和内容 emoji。
- 进度环、heatmap 和 streak 是主要数据视觉，不额外引入装饰性图表。
- MagicBento、AnimatedList 等参考效果只能局部使用，并服从暖色主题与 reduced motion。
- 拖拽柄、更多、完成按钮 hover 通过图标/描边变化表达，不添加底板或阴影。

### 7.9 Music

- 底部播放器是共享且唯一的音频控制器视觉入口。
- 播放、上一首、下一首、收藏、队列操作必须保持当前紧凑结构。
- 封面和进度可以承担视觉重心；控制按钮不应再用 hover 背景争夺注意力。
- 不创建第二套播放器或重复队列面板。

### 7.10 AI Chat

- AI Chat 延续暖纸和陶土色，而不是采用独立的蓝紫 AI 主题。
- 发送与接收消息依靠表面、对齐和有限主色区分。
- composer、附件、消息状态和工具结果复用现有实现。
- TweakCN application chat 主要参考结构、消息层级和细节，不覆盖 Kairos 色彩与字体。

### 7.11 桌面宠物

- 宠物图片、气泡和菜单可以更活泼，但气泡与菜单仍使用应用语义表面。
- 宠物窗口本身保持透明与 click-through 契约。
- 恢复宠物按钮属于 icon button；hover 只改变宠物图案或描边颜色，不增加背景或阴影。

## 8. 布局原则

### 8.1 桌面结构

- AppShell 管理 64 px 顶栏、路由内容、全局弹层和共享播放器。
- 普通内容区高度基于 `100vh - 64px`。
- Calendar/Music 需要为 80 px 底部播放器预留空间。
- 页面常规水平边距为 28–32 px，窄窗口降至 14–20 px。
- 数据密集页面优先使用 Grid 和 Flex 的自适应，而不是固定像素宽度堆叠。

### 8.2 对齐与密度

- 标题、说明和主要操作形成清晰的页头基线。
- 数据卡片可以紧凑，但卡片内部至少保留 12–16 px 呼吸空间。
- 同一区域优先左对齐，数字列可右对齐。
- 不使用无目的的大面积居中排版。

### 8.3 响应式行为

现有主要断点集中在约 960 px、760 px 和 650 px：

- 四列数据卡逐步降为两列、一列。
- 工具栏可折行为纵向，搜索框填满宽度。
- 顶栏在窄宽度隐藏导航文字和次要图标操作。
- 双月日期选择器在窄窗口显示单月。
- 弹窗宽度使用 viewport 约束，并保持内容可滚动。

Kairos 是桌面优先应用，但窄窗口不能出现不可操作的裁切。

## 9. 动效原则

- 普通颜色和边框过渡：约 160–180 ms。
- 面板、Toast、列表进入：约 220–280 ms。
- 使用现有 `cubic-bezier(.2,.8,.2,1)` 作为柔和运动基线。
- 页面切换、GooeyNav、AnimatedList、MagicBento、ShinyText 等属于有意图的品牌动效，必须局部、克制。
- 不通过 hover 阴影或背景膨胀制造动效。
- reduced motion 下取消非必要位移、缩放、粒子和连续动画。

## 10. 参考素材使用规则

所有 `references/` 素材均视为用户喜爱的候选参考，但必须按用途读取：

- TweakCN：主题、应用结构、聊天和数据密度
- shadcn：组件结构、状态完整性和可访问性
- React Bits：局部动效和富交互，不负责全局颜色与排版
- Stitch/legacy artifacts：历史视觉意图和溯源，不直接复制到运行时
- upstream source libraries：查阅实现细节，不作为默认视觉事实来源

使用前先在 `references/README.md` 确认类别和限制。

## 11. 当前设计债务与迁移原则

现有代码中仍有部分 hover 会添加背景、阴影或上浮，例如部分顶栏图标按钮、日程卡、习惯主按钮、弹窗关闭按钮和宠物恢复按钮。这些是需要渐进统一的既有设计债务，不代表新规范允许继续复制。

处理原则：

1. 新组件从一开始遵守本文档。
2. 修改到旧组件时，在任务范围内同步纠正其 hover。
3. 不用一个巨大的全局 `!important` 覆盖一次性“修复”所有页面。
4. 每次迁移都检查 hover、focus-visible、active/selected 和 disabled，避免修复 hover 后损害状态表达。
